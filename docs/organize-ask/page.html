3 手順ごとのカード

5 スクリプトが機械的に止める条件

スクリプトが意図して終了コード 0 以外にするのは、引数の誤りと、環境の点検の失敗である（捕まえていない例外でも、0 以外で終わる）。業務上のエラーは、JSON の error で返して終了コード 0 にする。

この表の終了コードは、main（vault_inbox.py の {{ln:vault-inbox/scripts/vault_inbox.py:main}} 行）と、argparse の既定の動作による。

条件終了コード出力実行して確かめたか
引数ファイルに --root を書いた（_check_file_options・{{ln:vault-inbox/scripts/vault_inbox.py:_check_file_options}} 行）2標準エラーに使い方とメッセージ確かめた（手順4）
引数ファイルに同じオプションを 2 回書いた・@ で始まる行（入れ子）を書いた2標準エラーにメッセージ未実行（コードの読解のみ）
必須のオプションがない（例: place の --dest）2標準エラーに argparse の表示未実行（argparse の既定）
resolve の --action に使えないオプションを付けた2標準エラーにメッセージ未実行（コードの読解のみ）
doctor に [NG] がある3標準出力に 1 行ずつの点検結果未実行（[NG] の状態を作っていない）
place の失敗: name_collision・source_missing・bad_name・place_failed・bad_destination0{"error": "…"}bad_destination・name_collision は確かめた
resolve の失敗: unknown_action・missing_argument・bad_path・file_missing・unknown_id0{"error": "…"}bad_path は確かめた
relate の失敗: unknown_id・unknown_kind0{"error": "…"}unknown_kind は確かめた
update-meta が未知の id0{"error": "unknown_id"}未実行
ロックが取れない0{"acquired": false, "holder": {…}}。止まるかは Claude の判断確かめた（session・pass とも）
meta.json が壊れ、バックアップもない1 のはず例外（MetaCorrupt）。呼び出し側に捕まえる処理がない未実行（コードの読解のみ）

6 判断の規則

ここでは、状態・分岐・聞き直しの規則を表にまとめる。数値はコードの定数から読んだ。

intake の status ごとの扱い

status意味（コードの条件）Claude の扱い（intake.md）
ready配置できる。全文を取り出して .vault-inbox/text/<id>.txt に保存済み1 件ずつ R1〜R6 を行う
duplicate同じ中身の資料が、登録済みか、同じ回の別ファイルにある（file_hash が同じ）inbox/ に残し、inbox-mark で記録する
unsupported拡張子が対象の形式ではない同上
extract_failed読み取れない（空・壊れた・ライブラリがない・暗号化）同上
skippedサブフォルダ、または対象外の名前（~$・. で始まる、.要約.md で終わる）同上
declined前に分類先が承認されず、それから内容が変わっていない分類先を聞き直さない
  • seen: 前の実行で inbox-mark 済みの資料は true になる。watch の 2 回目以降は、再通知しない。
  • hash: 内容の SHA-256。md は、プラグインが書くキー（要約・日付・関連・vault-inbox）を除いて計算する。書き換えても「編集された」と見なされない。

資料の状態と配置

  • 資料の状態は 2 つ。placing（記録を書いたが、まだ移していない）と active（移し終えた）。
  • place は、placing を保存してから原本を移し、active にして保存する。途中で止まったら、次の resume が続きを行う。
  • 分類先の階層は、project/・shared/ を含めて {{const:vault-inbox/scripts/vault_inbox/vault.py:DEPTH_LIMIT}} 階層まで。超えた分は切り詰める（clamp_dest）。
  • 大文字小文字だけが違う既存のフォルダがあれば、その綴りを使う（existing_spelling）。

scan の unresolved の kind

kind条件Claude が聞くこと（scan.md）
missing_and_new記録にあるのに見つからない資料と、記録にない新しい資料が、同時にある消えた資料ごとに「組み直す」「新規として登録する」「索引から外す」
missing消えた資料だけがある「索引から外す」か「保留する」
new新しい資料だけがある「新規として登録する」か「登録しない」
  • 内容が同じで場所だけ変わった資料は、moved として自動で追従する。ただし、候補がちょうど 1 組のときだけ。
  • 移動しながら編集された資料は、内容が変わるので見分けられず、missing_and_new になる。

ロック

名前ファイル持つ人（owner）意味
sessionlock.jsonorganize・watchorganize か watch が動いている
passpass.jsonorganize・watch・ask-record整理の 1 回の実行、または ask の関係の記録が、いま動いている
  • 古いロックと見なすまでの既定は {{const:vault-inbox/scripts/vault_inbox/lock.py:DEFAULT_STALE_AFTER}} 秒（watch は、自分で短い窓を指定する）。
  • ロックは、同じ名前の別の持ち主がいると取れない（acquire・{{ln:vault-inbox/scripts/vault_inbox/lock.py:acquire}} 行）。

ask の検索と上限

  • 返す件数の既定は {{default:vault-inbox/scripts/vault_inbox/index.py:search_with_total:limit}} 件。total は、それを超えた全件数。
  • {{const:vault-inbox/scripts/vault_inbox/index.py:_MIN_FTS_LEN}} 文字以上の語は全文検索の索引で引く。それより短い語は、全文を読んで部分一致で絞る。
  • 関係の種類の初期の語彙は {{const:vault-inbox/scripts/vault_inbox/meta.py:INITIAL_VOCABULARY}}。語彙にない種類は、kind-add で足すまで relate が unknown_kind を返す。
  • expand は、ヒットした資料と、関係で 1 つ隣の資料を返す。supersedes で差し替えられた古い版は除く。conflicts_with の組は conflicts に入る。
  • 聞き直しや、選択肢・候補・資料の件数の上限は、SKILL.md の本文に書いてある（下の「7」）。

7 Claude が実際に読む文章

ここからは、手順ごとに、実ファイルの全文と、実行した標準出力を並べる。

デモの順序は、次のとおり。

  • 実行1: organize の手順1〜6（inbox/ に、資料とサブフォルダを置いてある）。
  • ask: 実行1 のあとに、質問して関係を 1 件記録する。
  • 手作業: 議事録を編集し、議事録と見積メモを別のフォルダへ動かす（build.py が行う）。
  • 実行2: organize の手順3 以降。手順1・2 と、手順5 の snapshot-absorb・unlock は省いた（ロックを取らず、基準も保存せずに実行した）。

実行1 と実行2 は、同じ Vault に対して続けて行った。

そのあと、議事録をさらに編集して別のフォルダへ動かし、見積メモは編集せずに別のフォルダへ動かした。

  • 見積メモは、中身が同じなので、moved に入る（自動で追従した）。
  • 議事録は、移動と編集が重なったので、unresolved の missing_and_new に入る。
{{run:scan_moved}}

Claude は、missing_and_new を、AskUserQuestion の選択肢で利用者に聞く。次は、scan.md の書式から作った例である。
